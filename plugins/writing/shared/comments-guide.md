# 검토 의견 작성 규칙

- 저장 위치: 검토 폴더(`.{대상 문서 이름}.review/`)의 `comments.jsonl` 하나
- 필드, 타입, 허용 값: `comments.schema.json`에서 규정
  - 이 문서에는 스키마로 표현할 수 없는 규칙만 기술
- 형식 검사
  - 저장할 때마다 hook이 `validate`로 검사하고, 오류가 나오면 해당 줄을 수정
  - hook은 명령에서 경로를 찾지 못하면 검사를 건너뛸 수 있으므로, 작성을 마친 뒤 `review.mjs validate`를 직접 실행하여 `ok` 확인

## 1. 파일 구조

- 첫 줄: 개요, `target`과 `content` 두 필드만 작성
  - `target`: 검토 폴더를 기준으로 한 대상 문서의 상대 경로(예: `../sample.md`)
  - `content`: 종합 의견의 마크다운 원문, 아래 세 절로 구성

    ```markdown
    ## 종합 의견

    {문서 전체에 대한 판단과 주요 의견 요약}

    ## 검토 기준

    - {검토 기준}

    ## 추가 관점

    - {추가 관점 원문. 없으면 "없음"}
    ```

    - 검토 기준: 한 줄에 하나씩 작성
      - 파일로 받은 기준: 확장자까지 붙인 파일 이름(예: `korean-writing-guide.md`)
      - skill로 받은 기준: skill 이름

- 둘째 줄부터: 한 줄에 의견 하나
- 검토할 때마다 파일 전체를 새로 작성

## 2. 필드

- `id`: 1부터 차례로 부여
- `category`: 항목 분류, 자유롭게 작성(예: 문장, 용어, 형식, 구조, 내용)
- `result`
  - `edit`: 고칠 문장을 제시할 수 있는 의견
  - `note`: 판단이 서지 않거나 사용자가 확인할 내용
- `title`: 수정할 내용이나 확인할 내용을 담은 한 문장
- `rule`: 근거 규칙, `{검토 기준} {절 번호}` 형식(예: `korean-writing-guide.md 2.6`)
  - 검토 기준의 이름: 개요의 검토 기준과 동일
  - 추가 관점에 근거한 의견: 관점의 짧은 요약
- `reason`: `title`을 반복하지 않는 한 문장
- `severity`
  - `required`: 규칙 위반, `rule` 필수
  - `optional`: 규칙을 위반하지 않은 개선 제안
- `location`: 의견이 가리키는 원고의 위치
  - 텍스트 파일 원고(`.md`, `.txt` 등): `minus`의 첫 줄(기타 의견은 `quote`)이 있는 줄 번호, 1부터 세는 정수
  - 텍스트 파일이 아닌 원고(PDF, docx 등): 원고에서 위치를 찾을 수 있는 자유 텍스트(예: `3쪽 둘째 문단`, `2.1절 Table 3`)
  - 문서 전체에 대한 의견처럼 위치를 정할 수 없는 의견: 생략
- `status`: `pending`
- `decision`, `instruction`: 작성 금지, 검토 페이지가 기록

## 3. 수정 의견의 diff

- `minus`: 원고의 연속된 줄을 글자 그대로 복사, 목록 기호와 들여쓰기도 유지
- 텍스트 파일 원고의 `minus`: 원고의 `location`번째 줄부터 한 줄씩 일치 필요
- 떨어진 위치를 함께 고쳐야 하면 의견 분리
- `plus`: 반영 후 원고에 그대로 들어갈 줄
  - 원문의 문단 구조 유지
  - 한 문단의 문장을 나눌 때는 한 줄에 이어서 작성
  - `plus`로 목록이나 새 문단을 만들면 앞뒤에 빈 줄(`""`) 추가

## 4. 기타 의견

- `quote`: 원고의 문장을 그대로 인용
- 텍스트 파일 원고의 `quote`: 첫 줄이 원고의 `location`번째 줄에 포함 필요
