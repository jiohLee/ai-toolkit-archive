# 검토 의견서 형식

- `reviewing-documents`와 `applying-review-decisions`가 함께 쓰는 형식이다.
- 검토 의견서는 사용자가 결정을 표시하고, `applying-review-decisions`가 그 표시를 읽는 파일이다. 사용자가 프롬프트 창에 일일이 입력하지 않도록 결정을 이 파일에 모은다.
- 검토 의견서는 대시보드처럼 쓴다. 문서에 반영한 의견은 지우고, 사용자가 아직 볼 의견과 현재 상황만 남긴다.

## 의견의 결과

- `수정`: 정답이 분명해 diff를 제시할 수 있는 의견
- `기타 의견`: 사용자의 판단이나 추가 정보가 필요해 diff를 제시할 수 없는 의견

## 의견의 상태

- `대기`: 아직 처리하지 않음. 새 의견의 초깃값
- `유지`: 사용자가 원문을 유지하기로 결정함. 재검토에서 같은 의견을 다시 제기하지 않도록 남긴다.
- `해당 없음`: 대상 문서가 바뀌어 의견이 더는 맞지 않음

대상 문서에 반영한 의견은 상태를 바꾸지 않고 검토 의견서에서 지운다. 지운 건수는 1.2절의 누적 반영에 남는다.

## 결정 표시

- `적용`: 의견을 대상 문서에 반영한다. 수정 의견은 diff를 반영하고, 기타 지시가 있으면 지시를 따른다.
- `유지`: 대상 문서를 고치지 않는다.
- `기타 지시`: 의견을 어떻게 반영할지 사용자가 적는 한 줄이다.
  - **`적용`에 체크해야 지시를 따른다.** 체크가 없으면 미결로 본다. 쓰다 만 지시가 문서에 들어가지 않게 하기 위해서다.
  - 일괄 결정의 `모두 적용`은 체크로 치지 않는다. 일괄 결정은 diff를 반영하므로 적어 둔 지시가 무시되기 때문이다.

기타 지시는 아래처럼 쓴다.

```markdown
- [x] 적용
- [ ] 유지
- 기타 지시: 서버 주소는 vpn.example.com이라고 쓴다
```

- 수정안 바꾸기: `수정안 대신 "접속에 실패하면"으로 쓴다`
- 빠진 정보 알려 주기: `발급에는 3영업일이 걸린다고 쓴다`
- 문장 지우기: `이 문장을 지운다`
- 범위 넓히기: `문서 전체의 "유저"를 "사용자"로 바꾼다`
- 위치 옮기기: `이 문단을 1장 맨 앞으로 옮긴다`

## 저장 위치

- 검토 의견서는 대상 문서 옆에 저장한다.
- 기본 이름은 `{대상 문서 이름}.review.md`다. `study-srs.md`의 검토 의견서는 `study-srs.review.md`다.

## 추가 관점

- 1.3절은 검토에 쓴 추가 관점의 기록이다.
- 항목은 `- **{검토 일자}**: {입력 종류}`로 쓰고, 그 아래에 관점을 번호 목록으로 쓴다.
  - 입력 종류는 `채팅 입력`이나 `파일`이다.
  - 채팅 입력은 원문을 큰따옴표로 쓰고, 파일은 경로를 인라인 코드로 쓴다.
  - 검토 일자와 입력 종류가 같은 항목이 이미 있으면 그 항목의 번호 목록에 이어 쓴다.
- 추가 관점이 없으면 `없음`이라고 쓴다.
- 1.3절은 재검토의 입력이 아니다. 이전 관점을 다시 적용하려면 사용자가 요청에 다시 넣는다.
- 사용자는 1.3절의 항목을 지울 수 있다.

## 템플릿

- 아래 구조를 그대로 쓴다.
- 항목 분류는 내용에 맞게 정하고 2장부터 번호를 매긴다.
- 의견 제목은 고칠 내용이나 확인할 내용을 문장으로 쓴다.
- `수정` 의견에는 diff를, `기타 의견` 의견에는 문서의 해당 부분을 인용문으로 넣는다.
- diff 안에 백틱 펜스가 있으면 바깥 펜스의 백틱을 더 길게 쓴다.
