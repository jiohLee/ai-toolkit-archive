# 검토 의견 작성 규칙

- 검토 의견은 검토 폴더(`.{대상 문서 이름}.review/`)의 `comments.jsonl` 하나에 쓴다.
- 필드, 타입, 허용 값은 `comments.schema.json`이 정한다. 이 문서에는 스키마로 표현할 수 없는 규칙만 쓴다.
- 저장하면 hook이 `validate`로 검사한다. 오류가 나오면 해당 줄을 고친다.

## 1. 파일 구조

- 첫 줄은 개요다. `target`과 `content` 두 필드만 쓴다.
  - `target`: 검토 폴더를 기준으로 한 대상 문서의 상대 경로. 예: `../sample.md`
  - `content`: 종합 의견의 마크다운 원문. 아래 세 절로 쓴다.

    ```markdown
    ## 종합 의견

    {문서 전체에 대한 판단과 주요 의견 요약}

    ## 검토 기준

    - {검토 기준 파일 이름이나 skill 이름}

    ## 추가 관점

    - {추가 관점 원문. 없으면 "없음"}
    ```

- 둘째 줄부터 의견을 한 줄에 하나씩 쓴다.
- 파일은 검토할 때마다 처음부터 다시 쓴다.

## 2. 필드

- `id`: 1부터 차례로 매긴다.
- `category`: 항목 분류. 문장, 용어, 형식, 구조, 내용처럼 자유롭게 쓴다.
- `result`: 고칠 문장을 제시할 수 있으면 `edit`, 판단이 서지 않거나 사용자가 확인할 내용이면 `note`로 쓴다.
- `title`: 수정할 내용이나 확인할 내용을 한 문장으로 쓴다.
- `rule`: 근거 규칙을 `{문서 이름} {절 번호}` 형식으로 쓴다. 예: `korean-writing-guide 2.6`. 추가 관점에 근거한 의견은 관점을 짧게 쓴다.
- `reason`: 한 문장으로 쓴다. `title`을 반복하지 않는다.
- `severity`: 규칙 위반은 `required`, 규칙을 위반하지 않은 개선 제안은 `optional`로 쓴다. `required`는 `rule`이 비어 있으면 안 된다.
- `line`: `minus`의 첫 줄(기타 의견은 `quote`)이 있는 원고의 줄 번호. 1부터 센다.
- `status`: `pending`으로 쓴다.
- `decision`, `instruction`: 쓰지 않는다. 검토 페이지가 기록한다.

## 3. 수정 의견의 diff

- `minus`는 원고의 연속된 줄을 글자 그대로 복사한다. 목록 기호와 들여쓰기도 그대로 둔다.
- `minus`의 첫 줄은 원고의 `line`번째 줄과 같아야 한다.
- 떨어진 위치를 함께 고쳐야 하면 의견을 나눈다.
- `plus`는 반영 후 원고에 그대로 들어갈 줄이다. 원문의 문단 구조를 유지한다. 한 문단의 문장을 나눌 때는 한 줄에 이어 쓴다.
- `plus`로 목록이나 새 문단을 만들면 앞뒤에 빈 줄(`""`)을 넣는다.

## 4. 기타 의견

- `quote`는 원고의 문장을 그대로 인용한다. 원고의 `line`번째 줄이 `quote`의 첫 줄을 포함해야 한다.
