## 1. 기본 원칙

- 예시의 `-` 줄은 Bad, `+` 줄은 Good.

### 1.1. 구성 단계

- 글의 구성 순서: 문장 → 문단 → 목록 → 표, 그림
- 내용에 구조가 드러나면 다음 단계로 이동.
  - 한 주제를 이루는 여러 문장: 문단
  - 나열이 섞인 문단: 목록
  - 같은 속성을 반복하는 목록 항목: 표
  - 순서, 흐름, 관계에 대한 설명: 그림
- 구조가 없는 내용은 현재 단계 유지. 한 문장으로 충분한 내용의 목록화나 표 구성은 지양.
- 길이는 수치가 아니라 각 절의 판단 신호와 읽는 사람의 부담을 기준으로 판단.

### 1.2. 요소별 문체

- 문단: 글 종류의 기본 문체(`korean-writing-guide.md` 1.1)
- 목록, 표의 셀, 그림 속 글: 명사구. 서술형 종결 어미(~한다)와 명사형 어미(~함, ~임)는 사용 금지. 번호 목록도 동일.
- 마침표: 서술하는 항목과 셀은 마침표로 종결. 이름만 나열한 항목, 열 제목, 레이블은 마침표 생략.

```diff
- - agent: 작업을 능동적으로 수행한다.
- - agent: 작업을 능동적으로 수행함.
+ - agent: 작업을 능동적으로 수행.
```

```diff
- | agent | 작업을 능동적으로 수행한다. |
+ | agent | 작업을 능동적으로 수행. |
```

## 2. 문단

### 2.1. 한 문단에서는 주제 하나만 다룬다

- 주제가 바뀌면 문단 분리.
- 판단 신호: 문단 전체를 대표하지 못하는 첫 문장

### 2.2. 핵심을 먼저 제시한다

- 결론이나 핵심을 먼저 제시하고, 보충 설명은 뒤에 배치.
- 효과: 결론을 알고 읽는 독자의 빠른 이해

```diff
- 프로그램이 동적으로 메모리를 할당하다 보면 메모리 영역에는 필요 없는 영역이 생기게 된다.
- 이런 필요 없는 영역을 해제하는 기능을 Garbage collection이라고 하며 이는 메모리 관리 기법 중의 하나이다.
+ garbage collection은 메모리 관리 기법 중의 하나이다.
+ 프로그램이 동적으로 할당했던 메모리 영역 중에서 필요 없게 된 영역을 해제하는 기능이다.
```

### 2.3. 길어진 문단은 나눈다

- 문단의 길이는 수치가 아니라 읽는 사람의 부담으로 판단.
- 판단 신호
  - 한 번에 파악하기 어려운 문단의 요점
  - 문단 안에 섞인 항목 나열
  - "또한", "그리고" 같은 접속 표현으로 계속 덧붙인 내용
- 주제가 둘이면 문단 분리(2.1절). 나열이 섞였으면 목록으로 변경(3.1절).

## 3. 목록

### 3.1. 나열은 목록으로 작성한다

- 여러 항목을 설명하는 긴 문단은 목록으로 변경.
- 순서가 있는 목록은 숫자, 순서가 없는 목록은 하이픈 사용.

```diff
- 진행 단계에서 대기는 결재자(리더)가 결재하기 전 상태를 안내하며, 진행중은 1차 결재자(리더)가 승인 후 최종 결재자가 결재 전까지의 상태를 안내한다. 승인은 결재자가 승인으로 결재를 완료한 상태를 안내한다.
+ 진행단계는 다음과 같이 구분한다.
+   - 대기: 결재자(리더)가 결재하기 전 상태
+   - 진행중: 1차 결재자(리더)가 승인 후 최종 결재자가 결재 전까지의 상태
+   - 승인: 결재자가 승인으로 결재를 완료한 상태
```

### 3.2. 깊어진 목록은 절이나 표로 바꾼다

- 하위 목록이 깊어져 흐름을 따라가기 어려우면 상위 항목을 절 제목으로 올리거나 표로 변경.
- 판단 신호: 하위 항목을 읽다가 상위 항목을 다시 확인해야 하는 상황

## 4. 표

### 4.1. 같은 속성을 반복하는 목록은 표로 작성한다

- 여러 항목이 같은 속성(이름, 역할, 조건 등)을 반복해서 설명하면 표로 작성.
- 판단 신호: 항목마다 같은 모양으로 반복되는 하위 목록

```diff
- - reviewer: Sonnet으로 실행한다. 검토 의견을 작성한다.
- - 반영 skill: Opus로 실행한다. 원고를 수정한다.
- - 검토 페이지: 모델을 사용하지 않는다. 결정을 입력받는다.
+ | 구성 요소 | 모델 | 하는 일 |
+ | :--- | :---: | :--- |
+ | reviewer | Sonnet | 검토 의견 작성 |
+ | 반영 skill | Opus | 원고 수정 |
+ | 검토 페이지 | 없음 | 결정 입력 |
```

### 4.2. 셀이 길어지면 목록으로 바꾼다

- 셀에 문장이 여러 개 들어가면 표 대신 목록 사용.
- 셀 길이의 기준: 명사구 하나

## 5. 그림

### 5.1. 순서와 관계는 그림으로 표현한다

- 순서, 흐름, 구성 요소 사이의 관계를 말로 설명하는 경우 그림을 함께 배치.
- 문서의 그림은 `design:drawing-figures` skill로 작성.
- 그림을 넣을 수 없는 글(대화 답변 등)에서는 번호 목록이나 표로 대체.

### 5.2. 그림의 요점을 본문에서 설명한다

- 그림의 단독 배치는 지양. 그림 앞이나 뒤에 그림이 보여 주는 요점을 한두 문장으로 설명.

## 6. 장과 절

### 6.1. 주제가 바뀌면 절을 나눈다

- 한 절이 주제를 둘 이상 다루면 절 분리.
- 절 제목만 읽어도 문서의 흐름이 보이도록 구성.
