## 1. 기본 원칙

### 1.1. 문체

- 글의 종류에 따라 다음 문체를 쓴다.
  - "~합니다"체: 대화 답변
  - "~한다"체: 문서. 사용자가 독자에 맞춰 지시하면 "~합니다"체로 쓴다.
  - 명사 또는 명사형 어미(~함, ~임): 커밋 메시지, PR 제목과 본문, Azure Boards work item의 설명과 코멘트
  - 그림 속 글: 레이블은 명사 또는 명사형 어미로, 설명 문장은 "~한다"체로 쓴다.
- 한 문서 안에서는 한 가지 문체만 쓴다.

### 1.2. 용어

- 학술, 과학, 공학 용어가 문서에 최초 등장할 경우 영문 용어(+약어)를 병기한다.
  - 형식은 `**국문 용어**(영문 용어, 약어)`로 쓴다. 앞에 나오는 국문 용어만 굵게 표시하고, 약어가 없으면 생략한다.
  - 예: **대규모 언어 모델**(Large Language Model, LLM), **하네스**(harness)

### 1.3. 문장 부호

- 나열에는 가운뎃점(`·`)을 쓰지 않는다.
- 따옴표와 낫표는 국립국어원 문장 부호 규정에 따라 쓴다.
  - 큰따옴표(`""`): 말이나 글을 직접 인용할 때 쓴다. 예: 실제로 던진 질문, 검색어, 답변 원문
  - 작은따옴표(`''`): 인용한 말 안에 있는 인용한 말, 마음속으로 한 말을 나타낼 때 쓴다. 특별히 강조할 부분에도 쓸 수 있다.
  - 홑낫표(`「」`): 소제목, 작품 제목, 규정 이름 같은 제목을 나타낼 때 쓴다. 작은따옴표로 대신 쓸 수 있다.

## 2. 문장 작성 원칙과 예시

- 예시에서 `-` 줄은 Bad, `+` 줄은 Good이다.

### 2.1. 필수 문장 성분을 생략하지 않는다

- 주어(~은/는/이/가), 필수 부사어(~에게), 목적어(~을/를)를 넣는다.
- 기술 문서는 누가, 누구에게, 무엇을 하는지가 분명해야 한다.

```diff
- 사용자의 추가 발화에 대기하기 위해 Recognizer.Expect Speech Instruction을 전송한다. 수신이 완료되면 모든 응답을 종료한 후 다시 발화 대기 상태로 전환한다.
+ 사용자의 추가 발화에 대기하기 위해 KVS는 Recognizer.Expect Speech Instruction을 Service Agent에 전송한다. Service Agent는 Recognizer.Expect Speech Instruction을 수신하면 모든 응답을 종료한 후 다시 발화 대기 상태로 전환한다.
```

### 2.2. 주어와 서술어를 호응시킨다

- 주체와 행위, 주체와 상태, 주체와 속성의 관계를 올바르게 표현한다.
- "~이유는"으로 시작한 문장은 "~때문이다"처럼 이유를 나타내는 서술어로 끝낸다.

```diff
- 카카오워크가 편리한 비즈니스 메신저인 이유는 카카오톡과 UI가 비슷하다.
+ 카카오워크가 편리한 비즈니스 메신저인 이유는 카카오톡과 UI가 비슷하기 때문이다.
```

### 2.3. 수식어는 수식받는 말 바로 앞에 둔다

- 수식어가 멀리 떨어져 있으면 무엇을 꾸미는지 모호해진다.

```diff
- 복잡한 소프트웨어의 설치 과정
+ 소프트웨어의 복잡한 설치 과정
```

### 2.4. 부사어와 서술어를 호응시킨다

- "절대로", "결코"는 부정문과, "반드시"는 긍정문과 어울린다.

```diff
- 다음의 사항을 탈퇴하기 전에 절대로 확인하라.
+ 다음의 사항을 탈퇴하기 전에 반드시 확인하라.
```

### 2.5. 조사를 올바르게 쓴다

- 문맥상 필요 없는 조사는 뺀다.
- 영어 단어 뒤에는 영어 발음에 맞는 조사를 쓴다. 예: Writing(라이팅)은
- 괄호가 있으면 괄호를 무시하고, 괄호 앞 단어에 맞춰 조사를 쓴다.

```diff
- SDK를 초기화를 한다.
+ SDK를 초기화한다.
```

### 2.6. 능동형 문장을 쓴다

- 한국어는 피동형으로 쓰면 번역체처럼 읽힌다.
- 사람이 하는 행위는 사람을 주체로 쓴다. 무생물을 주어로 내세워 피동형이나 사동형으로 쓰지 않는다.

```diff
- [승인] 버튼이 클릭되어야 결제 승인이 완료된다.
+ [승인] 버튼을 클릭해야 결제 승인이 완료된다.
```

```diff
- 로그인이 되어야 설정 페이지로 이동될 수 있다.
+ 로그인을 해야 설정 페이지로 이동할 수 있다.
```

### 2.7. 이중 부정 대신 긍정형 문장을 쓴다

- 이중 부정은 글을 늘이고, 독자가 뜻을 한 번 더 계산하게 만든다.
- 부정형 문장도 가능하면 긍정형으로 바꾼다.

```diff
- 휴게 시간은 소정 근로시간에 포함이 안 되지는 않는다.
+ 휴게 시간은 소정 근로시간에 포함된다.
```

```diff
- 대상이 아닌 유저에게 보상을 지급하지 않는다.
+ 대상인 유저에게만 보상을 지급한다.
```

### 2.8. 지시 대상을 분명히 쓴다

- 앞에서 설명한 대상을 대명사로 바꾸거나 생략하면, 독자는 대명사가 가리키는 대상을 찾으러 앞 문장으로 돌아가야 한다.
- 대명사 대신 대상의 이름을 다시 쓴다. 같은 종류의 대상이 여럿이면 어느 것인지 밝힌다.

```diff
- a는 b와 비슷한 개념이다. 그것은 c와도 비슷하다. 하지만 유사도로 치면 이전과 더 비슷하다.
+ a는 b와 비슷하다. a는 c와도 비슷하다. 하지만 유사도로 치면 a는 b와 더 비슷하다.
```

```diff
- 서버에서 온 요청을 받아 고객사 서버로 전달한다.
+ 카카오 i서버에서 온 요청을 받아 고객사 서버로 전달한다.
```

### 2.9. 모호한 표현 대신 구체적인 수치를 쓴다

- "조금", "잠시", "많이", "꽤"처럼 여러 해석이 가능한 표현 대신 수치를 쓴다.

```diff
- 서버가 생성되기까지 많은 시간이 소요된다.
+ 서버가 생성되기까지 3, 4분이 소요된다.
```

### 2.10. 핵심을 먼저 쓴다

- 결론이나 핵심을 먼저 쓰고, 보충 설명을 뒤에 쓴다.
- 독자는 결론을 알고 읽으므로 뒤의 내용을 더 쉽게 이해한다.

```diff
- 프로그램이 동적으로 메모리를 할당하다 보면 메모리 영역에는 필요 없는 영역이 생기게 된다.
- 이런 필요 없는 영역을 해제하는 기능을 Garbage collection이라고 하며 이는 메모리 관리 기법 중의 하나이다.
+ garbage collection은 메모리 관리 기법 중의 하나이다.
+ 프로그램이 동적으로 할당했던 메모리 영역 중에서 필요 없게 된 영역을 해제하는 기능이다.
```

### 2.11. 하나의 뜻에는 하나의 표현만 쓴다

- 같은 대상을 글 전체에서 같은 단어로 부른다.
- 같은 용어의 표기를 문서 전체에서 일관되게 유지한다.

```diff
- 고사양 게임을 하기 위해 고사양 본체가 필요하다.
- PC 정보를 파악하려면 CPU-Z, GPU-Z같은 컴퓨터 정보를 볼 수 있는 시스템 소프트웨어 유틸을 사용하면 된다.
+ 고사양 게임을 하기 위해 고사양 PC가 필요하다.
+ PC 정보를 파악하려면 CPU-Z, GPU-Z같은 PC 정보를 볼 수 있는 시스템 소프트웨어 유틸을 사용하면 된다.
```

### 2.12. 문장을 짧게 나눈다

- 문장을 잇는 성분("~하는데", "~지만", "~어서")을 기준으로 긴 문장을 나눈다.
- 미사여구와 불필요한 형용사를 줄인다.

```diff
- 기계식 키보드는 브랜드 선정에 앞서 축을 선택하고 브랜드를 고르게 되는데 대표적인 브랜드로는 필코나 레오폴드, 바밀로 같은 키보드 브랜드가 있지만 그 외에도 매우 다양한 브랜드가 있어서 기계식 키보드를 선택한다면 개발자의 선택폭이 넓어지게 된다.
+ 기계식 키보드를 구매할 때는 브랜드보다 스위치 축을 먼저 선택해야 한다.
+ 축을 선택했다면, 브랜드를 선정한다.
+ 필코, 레오폴드, 바밀로 같은 브랜드가 대표적이다.
+ 그 외에도 매우 다양한 브랜드가 존재한다.
```

### 2.13. 나열은 목록으로 쓴다

- 여러 항목을 설명하는 긴 문단은 목록으로 바꾼다.
- 가정이나 설명의 나열은 개조식으로 작성한다. 표나 간단한 안내 항목은 명사나 명사형(~임, ~함)으로 끝낼 수 있다.
- 순서가 있는 목록은 숫자로, 순서가 없는 목록은 하이픈으로 쓴다.

```diff
- 진행 단계에서 대기는 결재자(리더)가 결재하기 전 상태를 안내하며, 진행중은 1차 결재자(리더)가 승인 후 최종 결재자가 결재 전까지의 상태를 안내한다. 승인은 결재자가 승인으로 결재를 완료한 상태를 안내한다.
+ 진행단계는 다음과 같이 구분한다.
+   - 대기: 결재자(리더)가 결재하기 전 상태
+   - 진행중: 1차 결재자(리더)가 승인 후 최종 결재자가 결재 전까지의 상태
+   - 승인: 결재자가 승인으로 결재를 완료한 상태
```

### 2.14. 맞춤법과 외래어 표기를 지킨다

- 맞춤법, 띄어쓰기, 오탈자를 확인한다.
- 외래어는 국립국어원 한국어 어문 규범의 표기를 따른다.

```diff
- 어플리케이션, 비지니스, 컨텐츠, 콘트롤
+ 애플리케이션, 비즈니스, 콘텐츠, 컨트롤
```
