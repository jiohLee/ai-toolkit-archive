# 작업 자료

아래 파일의 원문이 context에 없으면 먼저 읽는다. 요약만 있으면 없는 것으로 본다.

- `${CLAUDE_PLUGIN_ROOT}/shared/review-report-format.md`

# 요청 인자

`$ARGUMENTS`

# 절차

1. 검토 의견서를 찾아 읽는다. 찾을 수 없으면 사용자에게 묻고 멈춘다. 대상 문서는 메타 정보의 링크로 찾는다.
2. 상태가 `대기`인 의견만 모은다. 이미 처리한 의견을 다시 고치지 않기 위해서다.
3. 1.4절의 일괄 결정을 확인한다. 모두 적용과 모두 유지를 함께 표시했으면 일괄 결정을 무시하고 모순으로 보고한다.
4. 아래 표에 따라 의견별 처리를 정한다.

   | 표시 | 결과가 수정인 의견 | 결과가 기타 의견인 의견 |
   | :--- | :--- | :--- |
   | 적용 | diff를 반영 | 수정안을 작성해 반영하고 전후를 보고 |
   | 적용과 기타 지시 | 지시를 따름 | 지시를 따름 |
   | 유지 | 변경 없음 | 변경 없음 |
   | 유지와 기타 지시 | 변경 없음. 지시를 따르지 않았다고 보고 | 변경 없음. 지시를 따르지 않았다고 보고 |
   | 적용과 유지 동시 표시 | 반영하지 않고 모순으로 보고 | 반영하지 않고 모순으로 보고 |
   | 기타 지시만 작성 | 일괄 결정과 상관없이 미결로 보고 | 미결로 보고 |
   | 표시 없음 | 일괄 결정을 따르고, 일괄 결정도 없으면 미결로 보고 | 미결로 보고 |

   - 기타 지시는 `적용`에 체크했을 때만 따른다. 기타 지시만 적은 의견은 `적용` 체크가 필요하다는 이유로 보고한다. 쓰다 만 지시가 문서에 들어가지 않게 하기 위해서다.
   - 기타 지시의 뜻이 모호하거나 기타 의견의 수정안을 쓸 정보가 부족하면, 추측으로 고치지 않고 미결로 보고한다.
   - 의견이 묻는 내용 중 일부만 지시로 답할 수 있으면 일부 반영으로 처리한다. 답한 부분만 고치고, 답이 없는 부분은 추측으로 채우지 않는다.
5. 대상 문서를 고친다.
   - 고치기 전에 `git ls-files --error-unmatch {대상 문서}`로 대상 문서가 git에 추적되는지 확인한다. 추적되지 않거나 git 저장소가 아니면 "반영 후 수정 전 내용을 복구할 수 없다"고 먼저 알린다. 사용자가 반영을 요청했으므로 멈추지 않고 계속한다.
   - diff의 `-` 줄을 대상 문서에서 찾아 `+` 줄로 바꾼다.
   - `-` 줄이 없으면 그 의견을 실패로 보고한다. 검토 후 사용자가 문서를 고쳤을 수 있으므로 비슷한 문장을 찾아 고치지 않는다.
   - `-` 줄이 여러 곳에 있으면 위치로 특정하고, 특정할 수 없으면 실패로 보고한다.
   - 한 의견의 diff 중 일부라도 찾지 못하면 그 의견 전체를 실패로 보고한다.
   - 기타 의견의 인용문이 대상 문서와 다르면 위치와 내용으로 현재 문장을 찾아 현재 문장을 기준으로 처리하고, 인용문과 현재 문장을 함께 보고한다. 앞선 의견을 반영하면서 문장이 바뀌었을 수 있기 때문이다. 현재 문장을 찾을 수 없으면 실패로 보고한다.
6. 검토 의견서를 갱신한다. 이 파일은 대시보드이므로 사용자가 아직 볼 의견과 현재 상황만 남긴다.
   - 반영한 의견: 대상 문서를 고친 의견을 본문과 목차에서 지운다. 의견이 남지 않은 항목 분류는 장째로 지운다.
   - 일부 반영한 의견: 지우지 않는다. 대시보드에는 아직 할 일이 남은 의견이 보여야 하기 때문이다. 제목, 사유, 인용문을 남은 내용으로 고치고, 체크 표시와 기타 지시를 비운 뒤 `대기`로 둔다. 비우지 않으면 다음 반영에서 같은 지시를 다시 처리하게 된다. 누적 반영에는 더하지 않는다.
   - 남은 의견의 상태: 유지한 의견은 `유지`로 바꾼다. 모순, 미결, 실패로 보고한 의견은 `대기`로 둔다.
   - 남은 의견의 체크 표시와 기타 지시: 일부 반영한 의견 외에는 그대로 둔다. 사용자가 고쳐서 다시 실행할 수 있어야 하기 때문이다.
   - 번호: 남은 장과 의견의 제목 번호를 순서대로 다시 매긴다. 목차와 본문에서 의견 번호를 가리키는 부분도 함께 고친다.
   - 위치와 인용문: 남은 의견의 줄 번호와 기타 의견의 인용문을 현재 대상 문서에 맞춘다. 수정 의견의 diff는 고치지 않는다.
   - 검토 통계: 남은 의견을 기준으로 다시 계산하고, 누적 반영에 이번에 반영한 건수를 더한다.
   - 종합 의견: 남은 의견을 기준으로 다시 쓴다. 모순, 미결, 실패 의견은 새 번호와 이유를 적고, 가장 먼저 결정할 의견을 밝힌다. 남은 의견이 없으면 그 사실을 쓴다.
   - 일괄 결정: 표시를 비운다. 표시를 남기면 재검토나 다음 반영에서 사용자가 보지 못한 의견까지 처리될 수 있기 때문이다.
   - 파일: 남은 의견이 없어도 지우지 않는다. 누적 반영과 추가 관점의 기록이 남기 때문이다.
7. 사용자에게 아래 내용을 보고한다. 커밋은 사용자가 요청할 때만 한다.
   - 적용, 일부 반영, 유지, 미결, 실패 건수
   - 반영해 지운 의견의 이전 번호와 제목. 검토 의견서에서 사라지므로 이 보고가 처리 기록이 된다.
   - 일부 반영한 의견의 새 번호, 반영한 내용, 남은 내용
   - 모순, 미결, 실패로 보고한 의견의 새 번호와 이유
   - 기타 의견을 반영한 경우 수정 전후
   - 반영 결과를 확인하는 방법: 대상 문서가 git에 추적되면 `git diff`를 안내한다. 추적되지 않으면 수정 전 내용을 복구할 수 없다고 쓴다. 대화 기록에서 수정 전 문장을 찾으라고 안내하지 않는다. 대화 기록에 수정 전 문장이 없을 수 있기 때문이다.
