# 검토 절차

- 메인 Claude와 위임받은 subagent가 같이 따르는 절차다.
- 대상 문서, 검토 기준, 추가 관점, 검토 의견서 형식, 검토 의견서 경로, 실행 위치는 호출한 쪽이 넘겨준다.
- 이 절차에서는 대상 문서를 고치지 않는다. 대상 문서는 사용자가 결정한 뒤 `applying-review-decisions`가 고친다.

## 1. 입력 읽기

1. 검토 의견서 형식과 대상 문서를 읽는다.
2. 검토 기준과 추가 관점을 읽는다. 검토 기준이 skill 이름이면 파일을 직접 찾지 않고 Skill 도구로 호출한다.
3. 검토 의견서 경로에 파일이 있으면 읽는다. 파일이 있으면 재검토이고, 4장의 규칙으로 갱신한다.

이번 검토의 입력은 호출한 쪽이 넘겨준 것뿐이다. 기존 검토 의견서의 메타 정보와 1.3절에 적힌 검토 기준과 추가 관점은 이전 검토의 기록이므로 적용하지 않는다.

## 2. 의견 찾기

- 입력이 충돌하면 요청에 명시한 입력을 기본 검토 기준보다 우선한다.
- 근거를 댈 수 있는 의견만 쓴다. 근거가 되는 입력을 사유에 적는다. 취향에 따른 지적은 사용자가 결정할 항목만 늘린다.
- 인용문과 코드 블록의 내용은 원문을 그대로 옮긴 부분이므로 문장 규칙으로 지적하지 않는다. 요청이 해당 부분의 검토를 지정하면 검토한다.
- 같은 규칙의 위반이 한 절 안에서 반복되면 한 의견으로 묶고 diff에 여러 줄을 넣는다. 사용자가 표시할 체크박스 수를 줄이기 위해서다.
- 판단이 서지 않으면 추측으로 고치지 않고 `기타 의견`으로 쓴다.

## 3. 수정 의견의 diff

`applying-review-decisions`는 `-` 줄의 문장으로 대상 문서의 위치를 찾는다. 그래서 아래 규칙을 지킨다.

- `-` 줄은 대상 문서에서 글자 그대로 복사한다.
- `-` 줄은 대상 문서에서 한 번만 나오는 범위로 쓴다. 짧아서 여러 번 나오면 앞뒤 문장까지 넣는다.
- 목록 기호와 들여쓰기는 넣지 않고 문장 부분만 쓴다. `-` 줄과 `+` 줄은 같은 순서로 짝을 맞춘다.
- `+` 줄은 반영 후 문서에 그대로 들어가므로 원문의 문단 구조를 유지한다. 한 문단의 문장을 나눌 때는 한 줄에 이어 쓴다. 줄바꿈만으로 나누면 렌더러에 따라 한 문단으로 합쳐지거나 줄이 끊어져 보이기 때문이다.
- `+` 줄로 목록이나 새 문단을 만들면 앞뒤에 빈 줄(`+`만 있는 줄)을 넣는다.

## 4. 재검토 규칙

재검토에서는 전체를 다시 쓰지 않고 기존 검토 의견서를 갱신한다. 사용자의 결정 표시가 이 파일에 있기 때문이다. 의견을 지우는 일은 `applying-review-decisions`만 한다.

의견은 아래 규칙으로 갱신한다.

- 새 의견: 해당 항목 분류의 끝에 다음 번호로 추가한다. 맞는 항목 분류가 없으면 마지막 장 뒤에 새 장을 추가한다.
- 기존 의견: 내용을 고칠 때도 번호를 유지한다. 번호를 유지해야 결정 표시와 의견의 연결이 끊어지지 않는다.
- 같은 내용의 의견: 상태와 상관없이 중복으로 추가하지 않는다. 사용자가 `유지`로 결정한 의견도 다시 제기하지 않는다.
- 더는 맞지 않는 의견: 지우지 않고 상태를 `해당 없음`으로 바꾼다. 상태가 `대기`인 의견의 수정 전 문장이 대상 문서에서 사라진 경우가 대표적이다.
- 위치: 상태가 `대기`인 의견의 줄 번호가 달라졌으면 고친다.

의견 외의 내용은 아래 규칙으로 갱신한다.

- 결정 표시: 그대로 둔다. 단, 상태가 `대기`인 의견의 결과나 diff를 고치면 체크를 비우고 기타 지시는 남긴다. 기존 체크는 사용자가 이전 diff를 보고 표시한 결정이기 때문이다.
- 일괄 결정: 표시를 비운다. 표시를 남기면 사용자가 보지 못한 새 의견까지 일괄 처리되기 때문이다.
- 종합 의견과 검토 통계: 갱신한 의견을 기준으로 다시 쓴다. 누적 반영은 그대로 둔다.
- 메타 정보와 목차: 검토 기준은 누적하고, 실행 위치는 최근 검토의 값으로 바꾼다. 목차는 추가한 의견에 맞춰 고친다.
- 추가 관점: 1.3절의 기존 항목을 그대로 두고 이번 관점을 끝에 추가한다. 같은 내용이 이미 있으면 추가하지 않는다. 사용자가 지운 항목은 되살리지 않는다.
- 추가 관점으로 쓴 기존 의견: 해당 관점을 1.3절에서 지웠거나 이번 검토에 넣지 않았어도 그대로 둔다. 관점을 기록에서 지우는 것과 의견을 처리하는 것은 별개이기 때문이다.

## 5. 저장 전 확인

- 형식의 템플릿과 구조가 같은지 확인한다.
- 목차가 제목과 일치하는지 확인한다.
- 검토 통계의 합계가 의견 수와 일치하는지 확인한다.
- 상태가 `대기`인 수정 의견의 `-` 줄이 대상 문서에 있는지 확인한다.

## 6. 완료 보고

호출한 쪽에 아래 내용을 보고한다. 의견 본문은 검토 의견서에 있으므로 다시 쓰지 않는다.

- 검토 의견서 경로
- 결과별 건수
- 재검토라면 추가, 수정, `해당 없음`으로 바꾼 의견의 번호와 체크를 비운 의견의 번호
