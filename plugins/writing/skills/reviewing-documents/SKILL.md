# 작업 자료

- 검토 절차: `${CLAUDE_SKILL_DIR}/references/review-procedure.md`
- 검토 의견서 형식: `${CLAUDE_PLUGIN_ROOT}/shared/review-report-format.md`
- 기본 검토 기준: `${CLAUDE_PLUGIN_ROOT}/shared/korean-writing-guide.md`

세 파일은 3단계에서 읽는다. 위임할 경우 메인 context에 불러올 필요가 없기 때문이다.

# 요청 인자

$ARGUMENTS

# 절차

1. 요청 인자와 대화에서 입력을 정리한다.
   - 대상 문서: 찾을 수 없으면 사용자에게 묻고 멈춘다.
   - 검토 기준: 기본 검토 기준에 요청이 지정한 파일 경로와 skill 이름을 더한다. 사용자가 기본 검토 기준을 빼라고 하면 뺀다.
   - 추가 관점: 외부 피드백 파일의 경로와 채팅 입력의 원문이다. 채팅 입력은 요약하지 않는다. 요약하면 사용자가 강조한 표현이 사라진다.
   - 검토 의견서 경로: 사용자가 지정하지 않으면 형식 문서의 저장 위치를 따른다. 대상 문서 옆의 `{대상 문서 이름}.review.md`다.
2. 실행 위치를 정한다. 아래 조건 중 하나라도 해당하면 subagent에 위임하고, 해당하는 조건이 없으면 메인에서 실행한다.
   - 대상 문서와 검토 기준 파일을 합쳐 1,000줄을 넘는다. 기본 검토 기준은 225줄로 계산하고, 나머지 파일은 읽지 않고 `wc -l`로 센다. 플러그인 폴더는 작업 폴더 밖이라 `wc`가 권한 확인을 부를 수 있기 때문이다.
   - 현재 세션에 진행 중인 다른 작업이 있다.
   - 현재 세션에서 대상 문서를 작성했거나 고쳤다. 작성 의도를 아는 상태로 검토하면 독자가 막히는 지점을 놓치기 때문이다.
   - 사용자가 분리를 요청했다.
3. 정한 위치에서 검토한다.
   - 메인 실행: 검토 절차를 읽고 따른다.
   - 위임: Agent 도구로 `general-purpose` subagent를 실행한다. subagent는 대화 기록을 보지 못하므로 아래 내용을 모두 프롬프트에 넣는다. 경로는 절대 경로로 쓴다.

   ```text
   문서를 검토하고 검토 의견서를 저장한다. 대상 문서는 고치지 않는다.
   아래 검토 절차 파일을 읽고 그대로 따른다.

   - 검토 절차: ${CLAUDE_SKILL_DIR}/references/review-procedure.md
   - 검토 의견서 형식: ${CLAUDE_PLUGIN_ROOT}/shared/review-report-format.md
   - 대상 문서: {경로}
   - 검토 기준: {파일 경로와 skill 이름}
   - 추가 관점: {파일 경로, 채팅 입력 원문}
   - 검토 의견서: {경로}
   - 실행 위치: subagent

   완료 보고에는 검토 의견서 경로, 결과별 건수, 재검토라면 바뀐 의견의 번호만 쓴다.
   ```

4. 사용자에게 아래 내용을 보고한다.
   - 검토 의견서 경로와 실행 위치
   - 결과별 건수
   - 재검토라면 추가, 수정, `해당 없음`으로 바꾼 의견의 번호와 체크를 비운 의견의 번호
   - 다음 단계: 결정을 표시한 뒤 `/writing:applying-review-decisions {검토 의견서}`를 실행한다.
