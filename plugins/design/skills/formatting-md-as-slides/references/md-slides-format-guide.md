## 1. 원고 구성

- 원고는 **머리 설정 → 표지 → 목차 → 본문 → 마무리** 순서로 구성한다.
- 문서의 메타 정보 표와 머리말은 쓰지 않는다.
- 머리 설정에는 아래 항목을 쓴다. `title`은 발표 제목과 같게 쓴다.

```markdown
---
marp: true
theme: apple
title: 발표 제목
paginate: true
---
```

## 2. 슬라이드 나누기와 디렉티브

- 슬라이드는 `---`로 나누고, 앞뒤에 빈 줄을 하나씩 둔다.
- 슬라이드 하나에는 주제 하나만 담는다. 내용이 넘치면 글자를 줄이지 않고 슬라이드를 나눈다.
- 디렉티브는 슬라이드 맨 위에 HTML 주석으로 쓴다. 이름 앞의 `_`는 그 슬라이드에만 적용한다는 뜻이다.
- 디렉티브가 아닌 HTML 주석은 발표자 노트가 되어 슬라이드에 보이지 않는다.

<div align="center">

| 디렉티브 | 동작 |
| :---: | :--- |
| `_class` | 3장의 배치 클래스를 지정한다 |
| `_paginate: false` | 쪽 번호를 숨긴다 |
| `_header`, `_footer` | 머리글과 꼬리글을 넣는다. 링크가 있으면 값을 작은따옴표로 감싼다 |

</div>

*Table 1. 자주 쓰는 디렉티브*

## 3. 배치 클래스

- 슬라이드 배경은 라이트(`#ffffff`)와 다크(`#272729`) 두 가지만 쓴다.
- 클래스를 쓰지 않으면 라이트 배경에 제목이 왼쪽에 놓이는 기본 슬라이드가 된다.
- 표지는 `hero`, 목차는 `toc`, 마무리는 `closing`을 쓰고, 표지와 마무리에는 `_paginate: false`를 함께 쓴다.

<div align="center">

| 클래스 | 용도 | 동작 |
| :---: | :--- | :--- |
| `hero` | 표지 | H1과 부제를 가운데에 쌓고, 마지막 문단의 링크를 버튼으로 표시한다 |
| `toc` | 목차 | 링크 목록을 한 칸에 8개씩 채우고, 항목이 많으면 칸을 늘린다 |
| `statement` | 장 구분, 핵심 문장 | H1과 문장 하나를 가운데에 크게 쌓는다 |
| `closing` | 마무리 | H1과 목록을 가운데에 쌓고, 마지막 문단의 링크를 버튼으로 표시한다 |
| `dark` | 어두운 배경 | 다른 클래스와 함께 쓸 수 있다. 예: `dark statement` |

</div>

*Table 2. 배치 클래스*

### 3.1. 표지

- 마지막 문단의 첫 링크는 채운 버튼, 둘째 링크는 테두리 버튼이 된다.
- 버튼이 필요 없으면 마지막 문단에 링크를 쓰지 않는다.

```markdown
<!-- _class: hero -->
<!-- _paginate: false -->

# 발표 제목

한 줄 부제

[목차로 이동](#2) [자료 보기](https://example.com)
```

### 3.2. 목차

- 목차는 표지 바로 다음 슬라이드에 `# 목차` 제목으로 작성한다.
- 항목은 슬라이드 제목으로 가는 링크 목록으로 작성한다. 링크 텍스트는 제목과 똑같이 쓰고, 앵커는 GitHub 방식을 따른다.
- 칸 수는 항목 수에 따라 정해진다. 9개부터 2칸, 17개부터 3칸, 25개부터 4칸이 된다.
- 칸이 늘수록 칸 너비가 줄어든다(3칸 257px, 4칸 187px). 링크 텍스트가 칸 너비보다 길면 줄이 바뀌어 아래쪽 여백을 침범할 수 있으므로, 14장의 방법으로 확인한다.
- 슬라이드 제목을 추가, 삭제, 수정하면 목차도 함께 고친다.

```markdown
<!-- _class: toc -->

# 목차

- [슬라이드 제목](#슬라이드-제목)
- [다음 슬라이드 제목](#다음-슬라이드-제목)
```

### 3.3. 장 구분

```markdown
<!-- _class: dark statement -->

# 장 제목

장의 핵심을 담은 한 문장
```

### 3.4. 마무리

- 목차로 돌아가는 링크는 `#2`처럼 슬라이드 번호로 쓴다.

```markdown
<!-- _class: closing -->
<!-- _paginate: false -->

# 정리

- 핵심 내용 1
- 핵심 내용 2

[목차로 돌아가기](#2)
```

## 4. 제목

- ATX 제목 문법(`# 제목`)을 사용한다.
- H1(`#`)은 슬라이드 제목에 쓰며, 슬라이드마다 한 번만 쓴다. 번호를 붙이지 않는다.
- H2 이하는 슬라이드 안의 소제목에 쓴다. 번호를 붙이지 않는다.
- 짧은 제목을 화면 너비에 맞춰 키우려면 `# <!-- fit --> 제목`으로 쓴다.

## 5. 빈 줄

- 제목, 문단, 목록, 코드 블록, 표, 독립 수식 블록, HTML 블록, 캡션 사이에는 빈 줄을 하나 둔다.
- HTML 태그 안에 마크다운을 쓸 때는 여는 태그 뒤와 닫는 태그 앞에 빈 줄을 둔다. 빈 줄이 없으면 안쪽의 마크다운이 처리되지 않는다.

## 6. 목록

- 순서가 없는 목록은 `-`를 사용한다.
- 순서가 중요한 절차는 `1.`, `2.`처럼 번호 목록을 사용한다.
- 하위 목록은 한 단계 내려갈 때마다 두 칸씩 들여쓴다. 번호 목록의 하위 목록은 번호 뒤 글자 위치에 맞춰 세 칸 들여쓴다.
- 방향키를 누를 때마다 항목을 하나씩 보여 주려면 순서 없는 목록은 `*`, 번호 목록은 `1)`로 쓴다. PDF에는 모든 항목이 한 번에 보인다.

## 7. 강조와 코드

- 강조는 `**굵게**`로 표시한다.
- 형광펜은 `<mark>`, 키보드 키는 `<kbd>`로 쓴다.
- 파일 경로, 명령, 설정 키, 코드 식별자는 인라인 코드(``` `...` ```)로 감싼다.
- 코드 블록은 여는 펜스에 언어를 명시한다. 디렉터리 트리나 일반 텍스트는 `text`로 명시한다.
- 슬라이드 나누기와 겹치므로 수평선은 `---` 대신 `<hr>`로 쓴다.

## 8. 수식

- 수식은 LaTeX 문법으로 작성한다.
- 본문 안의 수식은 `$...$`로 감싼다.
- 독립 수식은 여는 `$$`와 닫는 `$$`를 각각 별도 줄에 놓는다.
- 수식 유도에서 근거, 가정, 치환 관계에는 `\because`를 사용한다.
- 결론 수식에는 `\therefore`를 사용한다.
- 여러 단계의 유도는 `aligned`를 사용한다. `&`로 등호 등의 위치를 맞추고 `\\`로 줄을 나눈다.
- 행렬은 `bmatrix`, 벡터는 `\mathbf`를 사용한다.

## 9. 이미지와 표

### 9.1. 이미지

- 그림 파일은 `./figures/fNN-{name}.svg`에 둔다.
- 번호와 캡션이 있는 그림은 아래 형식을 쓴다. 그림 번호는 원고 전체에서 차례로 매긴다.
- 본문 영역의 높이가 391px이므로 `width`는 문서의 80%보다 작게 잡는다. 그림의 가로세로 비율에 맞춰 14장의 방법으로 확인한다.

```markdown
<div align="center">
  <img src="./figures/fNN-{name}.svg" width=40%>
</div>

*Figure N. {caption}*
```

- 캡션이 필요 없으면 Marp 이미지 문법을 쓴다. 크기는 `w:` 또는 `h:`로 정한다.
- 슬라이드 한쪽을 그림으로 채우려면 `bg`를 쓴다. 글은 나머지 영역에 놓인다.
- 그림자는 제품 사진에만 쓰고, 값은 `drop-shadow:3px,5px,30px,rgba(0,0,0,.22)`로 쓴다.

```markdown
![w:240](./figures/fNN-{name}.svg)

![bg right:40%](./figures/fNN-{name}.svg)
```

### 9.2. 표

- 번호와 캡션이 있는 표는 아래 형식을 쓴다. 표는 가운데에 놓이고, 표 번호는 원고 전체에서 차례로 매긴다.
- `<div>` 안에서 표 위아래의 빈 줄은 표 렌더링에 필요하므로 지우지 않는다.

```markdown
<div align="center">

| 열 제목 1 | 열 제목 2 |
| :---: | :--- |
| 내용 1 | 내용 2 |

</div>

*Table N. {caption}*
```

- 본문 영역의 너비를 모두 쓰는 표는 `<div>`와 캡션 없이 표만 쓴다.

## 10. 그리드와 카드

- 칸을 나눌 때는 `grid` 안에 `cell` 또는 `card`를 넣는다.
- 칸과 줄의 비율은 `style` 속성에 직접 쓴다. `style`을 쓰지 않으면 칸이 내용 수만큼 한 줄에 같은 너비로 놓인다.
- 칸에는 `cell`이나 `card` 클래스를 반드시 쓴다. 클래스가 없는 `<div>`는 9장의 가운데 정렬 래퍼로 처리되어 글자가 가운데에 놓인다.

<div align="center">

| 클래스 | 모양 | 용도 |
| :---: | :--- | :--- |
| `cell` | 테두리와 배경 없음 | 글과 그림을 나란히 놓는 칸 |
| `card` | 파란 테두리 | 항목을 나열하는 카드 |
| `card accent` | 파란 테두리와 반투명한 파란 배경 | 강조할 카드 |

</div>

*Table 3. 그리드 칸의 종류*

<div align="center">

| 배치 | `style` 값 | 쓰는 곳 |
| :---: | :--- | :--- |
| 2:3 비율 | `grid-template-columns: 2fr 3fr` | `grid` |
| 같은 너비의 네 칸 | `grid-template-columns: repeat(4, 1fr)` | `grid` |
| 왼쪽 고정 너비 | `grid-template-columns: 200px 1fr` | `grid` |
| 두 줄, 위에서 아래로 채움 | `grid-template-rows: 1fr 1fr` | `grid` |
| 칸 두 개 차지 | `grid-column: span 2` | `cell`, `card` |
| 줄 두 개 차지 | `grid-row: span 2` | `cell`, `card` |

</div>

*Table 4. 그리드 배치 값*

```markdown
<div class="grid" style="grid-template-columns: 2fr 3fr">
<div class="card">

**강조 없는 카드**

카드 내용

</div>
<div class="card accent">

**강조 있는 카드**

카드 내용

</div>
</div>
```

- 칸 안에 그림과 캡션을 넣을 때는 `cell` 안에 9.1절의 형식을 쓴다. 칸 안의 그림은 `h:`로 높이를 정한다.

```markdown
<div class="grid" style="grid-template-columns: 1fr 1fr">
<div class="cell">

- 왼쪽 칸의 목록

</div>
<div class="cell">
<div align="center">

![h:220](./figures/fNN-{name}.svg)

</div>

*Figure N. {caption}*

</div>
</div>
```

## 11. 인용문과 알림

- 인용문은 `>`로 쓴다.
- 알림은 GitHub 문법(`> [!NOTE]`)이 처리되지 않으므로 `callout` 클래스로 쓴다. 제목과 아이콘은 테마가 넣는다.
- 종류는 `note`, `tip`, `important`, `warning`, `caution`이다.

```markdown
<div class="callout note">

알림 내용

</div>
```

## 12. 출처와 각주

- 외부 문서에서 정의, 설명, 주장을 가져오면 출처를 단다.
- 출처가 하나면 꼬리글에 쓴다.
- 출처가 여러 개이거나 보충 설명이 있으면 각주 상자를 쓴다. 각주는 슬라이드마다 1부터 매기고, 두 줄까지만 쓴다.
- GitHub 각주 문법(`[^1]`)이 처리되지 않으므로, 본문에서는 인용한 문장의 마침표 앞에 `<sup>N</sup>`을 붙인다.
- 줄 끝이 그대로 줄바꿈이 되므로 각주 사이에 `<br>`을 쓰지 않는다.
- 출처 내용은 `[문서 이름: 가져온 내용](링크)` 형식으로 쓴다. 같은 문서에 언어별 판이 있으면 문서 이름 뒤에 `(국문)`, `(영문)`을 붙인다.
- 출처 링크는 가져온 문장을 하이라이트하는 텍스트 프래그먼트(`#:~:text=시작 문구,끝 문구`) 링크로 쓴다.
  - 시작 문구와 끝 문구는 단어 단위로 끊는다. 한국어는 조사가 붙은 어절을 통째로 쓴다.
  - 시작 문구는 문서 안에서 한 번만 나오는 문구로 고른다.
  - 공백(`%20`), 쉼표(`%2C`), 하이픈(`%2D`), 괄호(`%28`, `%29`)는 퍼센트 인코딩하고, 한글은 인코딩하지 않고 그대로 쓴다.
  - 리다이렉트되는 주소는 최종 주소를 쓴다.

```markdown
<!-- _footer: '출처: [문서 이름 (국문): 가져온 내용](https://example.com/page#:~:text=start%20phrase,end%20phrase)' -->

# 출처가 하나인 슬라이드

본문 내용
```

```markdown
# 출처가 여럿인 슬라이드

첫 번째 주장이다<sup>1</sup>. 두 번째 주장이다<sup>2</sup>.

<div class="footnotes">

<sup>1</sup> [문서 이름: 가져온 내용](https://example.com/a#:~:text=start%20phrase,end%20phrase)
<sup>2</sup> 링크 없이 덧붙이는 보충 설명이다.

</div>
```

## 13. 처리되지 않는 문법

<div align="center">

| 문법 | 결과 | 대신 쓰는 형식 |
| :---: | :--- | :--- |
| 알림 `> [!NOTE]` | 글자 그대로 보임 | `<div class="callout note">` |
| 각주 `[^1]` | 글자 그대로 보임 | `<sup>1</sup>`과 `<div class="footnotes">` |
| 작업 목록 `- [x]` | 글자 그대로 보임 | `☑` 같은 문자 |
| 수평선 `---` | 슬라이드가 나뉨 | `<hr>` |
| Mermaid | 코드 블록으로 보임 | SVG 그림 |

</div>

*Table 5. Marp에서 처리되지 않는 문법*

## 14. 렌더링 확인

- 다 쓴 뒤 Marp CLI로 PDF를 만들어 모든 슬라이드를 확인한다. `--html`은 `markdown.marp.html`의 `all`에 해당한다.
- 내용이 아래쪽 여백 80px을 침범하면 슬라이드를 나누거나 내용을 줄인다.
- 어두운 슬라이드에서는 글자와 링크가 읽히는지 함께 확인한다.

```bash
npx @marp-team/marp-cli@4.5.1 {원고}.md --theme-set {테마 CSS 경로} --html --pdf --allow-local-files
```
