# 마크다운 형식 가이드

- 아래 범위에는 적용하지 않는다.
  - AI에게 제공하는 지침 파일: `CLAUDE.md`, `.claude/` 아래 파일(rules, skills 등)
  - AI가 대화에서 하는 답변

## 1. 문서 메타 정보

- 문서 상단은 **문서 제목 → 메타 정보 표 → 개요 → 목차 → 본문** 순서로 구성한다.
- 메타 정보는 `항목`, `내용`의 두 열로 작성한다.
- 항목 열은 가운데 정렬하고 굵게 표시한다.
- 내용 열은 왼쪽 정렬한다.
- 필요한 항목만 작성한다. 문서의 특성에 따라 작성 상태, 연관 문서, 범위, 실행 환경 등을 넣는다.
- 개요와 출처는 메타 정보 표에 넣지 않는다. 개요는 2장, 출처는 11장의 각주 형식을 따른다.
- 메타 정보 표는 본문 표와 구분하여 캡션, 표 번호, 가운데 정렬용 HTML 래퍼를 붙이지 않는다. 본문 표의 번호에도 포함하지 않는다.

```markdown
# 문서 제목

| 항목 | 내용 |
| :---: | :--- |
| **작성 상태** | 초안 |
| **연관 문서** | [`README.md`](./README.md) |
```

## 2. 머릿말

- 머릿말은 메타 정보 표 아래, `#### 목차` 위에 인용문(`>`)으로 쓴다. 예시는 3장에 있다.
- 머릿말에는 문서의 목적과 다루는 내용을 짧게 요약하여 쓴다.

## 3. 목차

- 목차는 개요 바로 아래에 `#### 목차` 제목으로 작성한다.
- 본문 제목이 없으면 목차를 생략한다.
- 목차 항목은 본문 제목으로 가는 링크 목록으로 작성한다. 링크 텍스트는 번호를 포함해 제목과 똑같이 쓰고, 앵커는 GitHub 방식을 따른다.
- 장(H2), 절(H3), 소절(H4)을 모두 포함하고, 한 단계 내려갈 때마다 두 칸씩 들여쓴다.
- 각주는 목차에 넣지 않는다.
- 본문 제목을 추가, 삭제, 수정하면 목차도 함께 고친다.

```markdown
> 머릿말로써 문서의 목적과 다루는 내용을 짧게 요약하여 작성.

#### 목차

- [1. 장 제목](#1-장-제목)
  - [1.1. 절 제목](#11-절-제목)
    - [1.1.1. 소절 제목](#111-소절-제목)
- [2. 장 제목](#2-장-제목)
```

## 4. 제목

- ATX 제목 문법(`# 제목`)을 사용한다.
- H1(`#`)은 문서 제목에만 사용하며, 문서당 한 번만 작성한다. 문서 제목에는 번호를 붙이지 않는다.
- 장, 절, 소절에는 H2(`##`), H3(`###`), H4(`####`)를 사용한다.
- 목차 제목은 H4(`####`)로 작성한다.
- 장, 절, 소절 제목에는 `1.`, `1.1.`, `1.1.1.`처럼 번호 뒤에 마침표를 찍어 번호를 붙인다.

```markdown
# 문서 제목

## 1. 장 제목

### 1.1. 절 제목

#### 1.1.1. 소절 제목

{본문 내용}
```

## 5. 빈 줄

- 제목, 문단, 목록, 코드 블록, 표, 독립 수식 블록, HTML 블록, 캡션 사이에는 빈 줄을 하나 둔다.

## 6. 목록

- 순서가 없는 목록은 `-`를 사용한다.
- 순서가 중요한 절차는 `1.`, `2.`처럼 번호 목록을 사용한다.
- 하위 목록은 한 단계 내려갈 때마다 두 칸씩 들여쓴다. 번호 목록의 하위 목록은 번호 뒤 글자 위치에 맞춰 세 칸 들여쓴다.

## 7. 강조와 코드

- 강조는 `**굵게**`로 표시한다.
- 파일 경로, 명령, 설정 키, 코드 식별자는 인라인 코드(``` `...` ```)로 감싼다.
- 다른 문서를 가리킬 때는 ``[`문서 파일 이름`](문서 상대 경로)`` 형식의 링크로 쓴다. 다른 폴더의 문서도 링크 텍스트에는 파일 이름만 쓰고, 폴더 경로는 링크 주소에만 쓴다. 예: ``[`02-agent-loop.md`](./02-agent-loop.md)``, ``[`01-coding-agent.md`](../02-coding-agent/01-coding-agent.md)``
- 같은 문서 안의 장과 절을 가리킬 때는 `N절`, `N.N절`로 쓴다.
- 코드 블록은 여는 펜스에 언어를 명시한다. 디렉터리 트리나 일반 텍스트는 `text`로 명시한다.

## 8. 수식

- 수식은 LaTeX 문법으로 작성한다.
- 본문 안의 수식은 `$...$`로 감싼다.
- 독립 수식은 여는 `$$`와 닫는 `$$`를 각각 별도 줄에 놓는다.
- 수식 유도에서 근거, 가정, 치환 관계에는 `\because`를 사용한다.
- 결론 수식에는 `\therefore`를 사용한다.
- 여러 단계의 유도는 `aligned`를 사용한다. `&`로 등호 등의 위치를 맞추고 `\\`로 줄을 나눈다.
- 행렬은 `bmatrix`, 벡터는 `\mathbf`를 사용한다.

## 9. 이미지

- 문서에 이미지를 삽입하거나 수정할 때 아래 형식을 그대로 따른다.

```markdown
<div align="center">
  <img src="./figures/fNN-{name}.svg" width=80%>
</div><br>

*Figure N. {caption}*
```

## 10. 표

- 문서에 표를 삽입하거나 수정할 때 아래 형식을 그대로 따른다.
- `<div>` 안에서 표 위아래의 빈 줄은 표 렌더링에 필요하므로 지우지 않는다.

```markdown
<div align="center">

| 열 제목 1 | 열 제목 2 |
| :---: | :--- |
| 내용 1 | 내용 2 |

</div>

*Table N. {caption}*
```

## 11. 각주

- 외부 문서에서 정의, 설명, 주장을 가져오면 GitHub 각주 문법으로 출처를 단다. 본문 흐름에서 벗어나는 보충 설명도 각주로 뺄 수 있다.
- 본문에서는 인용한 문장의 마침표 앞에 `[^N]`을 붙인다.
- 각주 정의(`[^N]: 내용`)는 문서 마지막에 번호 순서대로 한 줄에 하나씩 모아 쓴다. GitHub가 각주를 문서 끝에 모아 렌더링하므로 `## 참고 문서` 같은 제목은 달지 않는다.
- 각주 내용은 아래 둘 중 하나로 쓴다.
  - 외부 문서 출처: `[문서 이름: 가져온 내용](링크)` 형식으로 쓴다. 같은 문서에 언어별 판이 있으면 문서 이름 뒤에 `(국문)`, `(영문)`을 붙인다.
  - 보충 설명: 링크 없이 내용만 쓴다.
- 출처 링크는 가져온 문장을 하이라이트하는 텍스트 프래그먼트(`#:~:text=시작 문구,끝 문구`) 링크로 쓴다.
  - 시작 문구와 끝 문구는 단어 단위로 끊는다. 한국어는 조사가 붙은 어절을 통째로 쓴다.
  - 시작 문구는 문서 안에서 한 번만 나오는 문구로 고른다.
  - 공백(`%20`), 쉼표(`%2C`), 하이픈(`%2D`), 괄호(`%28`, `%29`)는 퍼센트 인코딩하고, 한글은 인코딩하지 않고 그대로 쓴다.
  - 리다이렉트되는 주소는 최종 주소를 쓴다.
- 각주 이름은 숫자만 쓰고, 본문에서 처음 참조한 순서대로 1부터 매긴다.
- 같은 문서라도 하이라이트 범위가 다르면 번호를 따로 매긴다. 같은 범위를 다시 인용하면 같은 번호를 쓴다.

```markdown
LLM 하나는 텍스트로만 응답한다[^1]. 본문 흐름을 끊는 설명은 각주로 뺀다[^2].

[^1]: [문서 이름 (국문): 가져온 내용](https://example.com/page#:~:text=start%20phrase,end%20phrase)
[^2]: 링크 없이 덧붙이는 보충 설명이다.
```
